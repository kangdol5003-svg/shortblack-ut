# shortblack-ut

롱블랙 모바일 화면을 재현한 UT(사용성 테스트)용 프로토타입입니다. **롱블랙 공식 서비스가 아닙니다.**
노트 본문은 자리표시 문장이고, 사용자 정보는 가명(김파이)입니다.

## 주소 (GitHub Pages, `docs/` 폴더)
| 주소 | 내용 |
|---|---|
| `/` | **BASE · 공통 반영 페이지**: V1~V5의 공통 기준본. 오른쪽 아래 "UT 버전 관리"를 누르면 버전 목록이 나옴 |
| `/v1/` ~ `/v5/` | 버전별 UT 화면 |
| `/v1/#ut` | 참가자용. 화면 왼쪽 아래의 버전 표시(UT-V1)를 숨김. "프로토타입 · 공식 서비스 아님" 표시는 남음 |

## 폴더
| 위치 | 내용 |
|---|---|
| `base/longblack_v0.html` | 공통 기준본(가명 처리됨). 다른 대화에서 고친 원본은 `--ingest`로만 넣는다 |
| `versions/v1.json` ~ `v5.json` | 버전마다 고유한 수정(`edits` 찾아 바꾸기 / `css` / `js`)과 기록(`purpose`, `log`) |
| `pseudonym.json` | 가명(이름·이메일) |
| `build.py` | 기준본 + 버전 수정 → `docs/` (Pages) 또는 `out/` (Claude 아티팩트) |
| `test_ut.py` | 헤드리스 크롬 확인 (`out/` 기준) |
| `docs/` | 게시되는 결과물. **직접 고치지 않는다** — 다시 빌드하면 덮어써짐 |

## 고치는 법
**버전 하나만** (예: V3)
1. `versions/v3.json`의 `edits`에 `{"find": "기준본에 정확히 1번 나오는 문자열", "replace": "바꿀 내용"}` 추가 (또는 `css`/`js`)
2. `log`에 `{"date": "...", "what": "무엇을 보고 → 무엇을 바꿨나"}` 추가
3. `python3 build.py --pages v3 base` → `docs/v3/`와 BASE의 목록만 바뀜. 커밋 메시지에 `V3:` 접두

**공통 수정** (BASE → 전체)
1. 새 원본: `python3 build.py --ingest 새원본.html` (가명 자동 적용)
2. `python3 build.py --pages` → BASE와 V1~V5 모두 다시 만듦. 버전별 고유 수정은 유지됨
3. 어떤 버전의 `find`가 새 기준본에서 0번/여러 번 나오면 **그 버전만 빌드가 멈추고** 알려 줌 → 그 버전 수정을 고친 뒤 다시 빌드
4. 커밋 메시지에 `BASE:` 접두

## 주의
- 이 저장소는 공개입니다. 실명·연락처를 넣지 마세요(`build.py`가 가명 처리 안 된 기준본을 거부합니다).
- 기준본의 문장스크랩 데이터에는 롱블랙 노트 원문 문장이 들어 있습니다.
